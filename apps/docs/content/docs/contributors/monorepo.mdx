The repo is a hybrid pnpm + Cargo workspace, driven by a top-level `justfile`.

## Top-level

```
mikoto/
├── apps/             # deployable services and end-user apps
├── packages/         # shared TypeScript packages (pnpm workspace)
├── crates/           # shared Rust crates (Cargo workspace)
├── examples/         # example Rust bots
├── data/             # local-only storage for RustFS, gitignored
├── docker-compose.yml
├── justfile          # repo-level task recipes
├── Cargo.toml        # Rust workspace root
├── pnpm-workspace.yaml
└── package.json
```

## `apps/`

| Path              | Language        | Description                              |
| ----------------- | --------------- | ---------------------------------------- |
| `client`          | TS/React        | Web client (Vite, port 3510)             |
| `superego`        | Rust            | API + WebSocket server (Axum, port 3511) |
| `content-proxy`   | Rust            | Optional third-party media proxy         |
| `desktop`         | TS/Electron     | Desktop wrapper around the web client    |
| `mobile`          | TS/React Native | Mobile app (WIP)                         |
| `design-language` | TS              | Design system / Storybook                |
| `docs`            | TS/Next.js      | This documentation site                  |

## `packages/`

| Path               | Description                                                                        |
| ------------------ | ---------------------------------------------------------------------------------- |
| `mikoto.js`        | The JS/TS client SDK consumed by the web client and external integrations.         |
| `permcheck`        | Tiny shared bitset permission checker used by both client and any JS integrations. |
| `mikoto-crypto`    | Crypto primitives shared across packages.                                          |
| `mikoto-ui`        | Cross-app UI primitives (separate from the client's Chakra-based design system).   |
| `lexical-markdown` | Custom Lexical nodes + serializer for Mikoto's markdown-flavored editor.           |
| `tsconfig`         | Shared `tsconfig` base that other packages extend.                                 |

## `crates/`

| Path              | Description                                                                                       |
| ----------------- | ------------------------------------------------------------------------------------------------- |
| `mikoto-client`   | Rust client SDK — for bots and server-side integrations.                                          |
| `mikoto-avatars`  | Procedural avatar generator (used as a fallback when a user has no uploaded avatar).              |
| `openapi-codegen` | Internal codegen tool that converts the superego OpenAPI schema into TS bindings for `mikoto.js`. |

## The justfile

[Just](https://github.com/casey/just) is the task runner; run `just` to
list every recipe. They fall into four groups:

- **Dev servers** — `just run-core` (superego, content-proxy and the
  client in parallel), `just run-superego`, `just run-client`,
  `just run-client-prod`, `just run-docs`.
- **Checks** — `just typecheck`, `just test`, `just lint`,
  `just lint-fix`, `just format`.
- **Codegen** — `just generate` regenerates superego's `api.json`, then
  the `mikoto.js` TS bindings, then the Rust `mikoto-client` bindings.
- **Database & services** — `just migrate`, `just seed`,
  `just new-migration`, `just reset-dev-env`, and friends.

There are no per-project task files: Rust steps run across the Cargo
workspace (`cargo check --workspace`, etc.) and TypeScript steps run
across the pnpm workspace with `pnpm -r`.

## pnpm and Cargo

- **JS:** `pnpm-workspace.yaml` declares `apps/*` and `packages/*` as
  workspace members. Use `workspace:*` in package.json `dependencies`
  to depend on a sibling package without versioning headaches.
- **Rust:** `Cargo.toml` at the root declares an explicit list of
  workspace members. Add new crates to that list when you create them.
