---
title: Media & CDN
description: Avatar uploads, message attachments, and the S3-compatible storage layer.
---

Media in Mikoto goes through superego's `/cdn` routes and lands in an
S3-compatible bucket. Locally that's [RustFS](https://rustfs.io/);
in production it's whichever S3 you configure.

## Upload flow

1. Client sends a `multipart/form-data` POST to `/cdn/...`.
2. Superego validates content type and size against the configured
   limits, generates a key, writes the object to S3 via `rust-s3`,
   and returns the canonical URL.
3. Downloads go through `/cdn/<key>` so the bucket can stay private —
   superego signs and streams.

### Why proxied downloads?

Two reasons:

- Lets us add per-request authorization (e.g., gating attachments by
  space membership) without touching the bucket policy.
- Lets us swap the S3 backend without changing public URLs.

If you're sure you want direct-from-S3 downloads, you can configure
the bucket public and bypass the proxy — but the default and intended
flow is through superego.

## Local storage (RustFS)

`docker compose up -d` starts RustFS on:

- `localhost:35103` — S3 API
- `localhost:35104` — web console (creds: `rustfs` / `password`)

The bucket name is `mikoto`. `just reset-dev-env` re-creates it
automatically via `mc`.

## Config

All under the `S3_*` env vars (see `apps/superego/src/env.rs::S3Env`):

```bash
S3_ACCESS_KEY=rustfs
S3_SECRET_KEY=password
S3_ENDPOINT=localhost
S3_PORT=35103
S3_BUCKET=mikoto
S3_USE_SSL=false
# S3_REGION=auto   # optional; defaults vary by provider
```

For a real S3-compatible provider (Backblaze B2, Cloudflare R2, AWS
S3, etc.), drop `S3_PORT`, set `S3_USE_SSL=true`, and use the
provider's endpoint.

## Image processing

Avatar uploads are run through the `image` crate to:

- Validate the bytes actually decode as an image.
- Generate downscaled variants (small / medium / large).
- Strip EXIF so we don't leak camera GPS coords by accident.

When a user has no uploaded avatar, the client falls back to a
procedural avatar generated by the `mikoto-avatars` crate. That
crate is a pure Rust library with no S3 dependency — it's invoked
on-demand to render PNGs.

## Content proxy

`apps/content-proxy` is a separate small Rust service that fetches
third-party media (link previews, OpenGraph thumbnails) and re-serves
it from a Mikoto-owned origin. It exists so the client never embeds
raw third-party URLs that could carry tracking pixels or leak the
user's IP.

It's optional for local dev — link previews degrade gracefully if it
isn't running.
