The REST surface is built on Axum and exposed through `aide`'s
`ApiRouter`, which threads request/response types into a generated
OpenAPI 3.1 schema.

## Live schema

Two endpoints, both served by superego itself:

- **`/api.json`** — the raw OpenAPI document.
- **`/scalar`** — an interactive renderer powered by
  [Scalar](https://scalar.com). Open
  [http://localhost:3511/scalar](http://localhost:3511/scalar) after
  running `just run-core`.

The schema is also committed to the repo as
`apps/superego/api.json` and regenerated by `cargo run --bin dump_api`.
This snapshot is what `mikoto.js` regenerates its typed client from.

## Route organization

Routes are grouped by domain under `src/routes/`. The top-level layout
(from `routes/mod.rs::build_app_router()`):

| Mount point | Module | Notes |
| ----------- | ------ | ----- |
| `/account` | `account` | Login, signup, refresh, password reset, email verify |
| `/bots` | `bots` | Bot registration and tokens |
| `/cdn` | `cdn` | Media upload and retrieval |
| `/handles` | `handles` | Username + custom domain handles |
| `/users` | `users` | User profiles |
| `/relations` | `users::relations` | Friends, blocks, requests |
| `/dm` | `dm` | Direct message channels and messages |
| `/spaces` | `spaces` | Spaces (servers) |
| `/spaces/:spaceId/channels` | `channels` | Channels inside a space |
| `/spaces/:spaceId/channels/:channelId/messages` | `channels::messages` | Messages |
| `/spaces/:spaceId/channels/:channelId/voice` | `channels::voice` | LiveKit token mint |
| `/spaces/:spaceId/channels/:channelId/documents` | `channels::documents` | Y.js document metadata |
| `/spaces/:spaceId/members` | `spaces::members` | Membership |
| `/spaces/:spaceId/roles` | `spaces::roles` | Roles + permission bitsets |
| `/spaces/:spaceId/bans` | `spaces::bans` | Bans |
| `/spaces/:spaceId/invites` | `spaces::invites` | Invite codes |
| `/push` | `push` | Web Push subscriptions |
| `/.well-known` | `well_known` | Public discovery metadata |
| `/ws` | `routes::ws` | Main WebSocket endpoint |
| `/collab/:channelId` | `channels::documents::collab_ws` | Y.js WebSocket |

## Writing a handler

```rust
#[derive(Serialize, JsonSchema)]
#[serde(rename_all = "camelCase")]
pub struct CreateSpaceResponse {
    pub space: SpaceExt,
}

async fn create_space(
    Account(account): Account,
    Json(payload): Json<CreateSpacePayload>,
) -> Result<Json<CreateSpaceResponse>, Error> {
    // ...
    Ok(Json(CreateSpaceResponse { space }))
}

pub fn router() -> ApiRouter<()> {
    ApiRouter::new()
        .api_route("/", post_with(create_space, |o| {
            o.id("createSpace").summary("Create a new space")
        }))
}
```

The handler signature drives the OpenAPI generation:

- Input types implementing `JsonSchema + DeserializeOwned` become
  request body / query parameters.
- Output types implementing `JsonSchema + Serialize` become response
  bodies.
- The `Account` extractor signals "this route requires auth"; the
  generated schema marks it accordingly.

Always use `api_route` (not `route`) for anything you want in the
OpenAPI document.

## Error handling

`crate::error::Error` implements `IntoResponse` to convert any error
into a JSON `{ code, message }` response with the right HTTP status.
Most route bodies just bubble errors with `?`:

```rust
let space = Space::find_by_id(space_id, db()).await?;
```

Bespoke errors live alongside the variant in `error.rs`. Use the
`Error::not_found("…")` / `Error::unauthorized("…")` constructors for
quick string-bodied responses; reserve named variants for things the
client needs to branch on.

## Auth

REST routes are protected by the `Account` extractor (defined in
`middlewares/auth.rs`). It pulls the bearer JWT off the
`Authorization` header, verifies the signature against the `SECRET`
env var, and loads the matching account row.

WebSocket auth is structured differently — see
[WebSocket protocol](/docs/superego/websocket).

## Consuming the schema from JavaScript

Don't hand-write request types. `packages/mikoto.js` regenerates a
typed Zodios client from `api.json` whenever you run:

```sh
pnpm --filter @mikoto-io/mikoto.js generate
```

The output ends up in `packages/mikoto.js/src/api.gen.ts`. See
[mikoto.js](/docs/packages/mikoto-js) for how the client wraps it.
