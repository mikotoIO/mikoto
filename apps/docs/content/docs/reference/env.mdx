Superego reads its config from a single `.env` at the repo root via
`dotenvy` + `serde-env`. The struct is in
[`apps/superego/src/env.rs`](https://github.com/mikoto-io/mikoto/blob/main/apps/superego/src/env.rs).

`.env.example` is the source of truth — copy it to `.env` and fill in
what you need.

## Superego

### Core

| Var            | Required | Default (dev)                                           | Description                                                                 |
| -------------- | -------- | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| `MIKOTO_ENV`   | ✓        | `DEV`                                                   | `DEV`, `TEST`, or `PRODUCTION`. Enables stricter CORS + HSTS in production. |
| `RUST_LOG`     | –        | `superego,content_proxy=info`                           | Standard `env_logger` filter.                                               |
| `SERVER_PORT`  | ✓        | `3511`                                                  | Port superego binds to.                                                     |
| `DATABASE_URL` | ✓        | `postgresql://postgres:postgres@localhost:35101/mikoto` | SQLx connect string.                                                        |
| `AUTOMIGRATE`  | –        | `true`                                                  | Run pending migrations on boot.                                             |
| `REDIS_URL`    | ✓        | `redis://localhost:35102`                               | Used for pub/sub and caching.                                               |

### Auth

| Var       | Required | Description                                                                       |
| --------- | -------- | --------------------------------------------------------------------------------- |
| `SECRET`  | ✓        | HMAC-SHA256 secret for JWTs. Must be high-entropy in production.                  |
| `ISSUER`  | ✓        | JWT `iss` claim (e.g., `mikoto.io`).                                              |
| `WEB_URL` | ✓        | Frontend origin. Used as the CORS allowlist in production and in email templates. |

### S3 (RustFS / S3-compatible)

| Var             | Required | Default (dev)                               |
| --------------- | -------- | ------------------------------------------- |
| `S3_ACCESS_KEY` | ✓        | `rustfs`                                    |
| `S3_SECRET_KEY` | ✓        | `password`                                  |
| `S3_ENDPOINT`   | ✓        | `localhost`                                 |
| `S3_PORT`       | –        | `35103` (RustFS); omit for public providers |
| `S3_BUCKET`     | ✓        | `mikoto`                                    |
| `S3_USE_SSL`    | ✓        | `false` locally, `true` in prod             |
| `S3_REGION`     | –        | provider-dependent                          |

### Mail (optional)

If unset, superego skips email sending and logs that smtp is disabled.

| Var                       | Description                                          |
| ------------------------- | ---------------------------------------------------- |
| `MAIL_HOST`               | SMTP server host (use `localhost` + MailHog locally) |
| `MAIL_PORT`               | SMTP port (MailHog is `35109`)                       |
| `MAIL_SECURE`             | `true` for TLS                                       |
| `MAIL_USER` / `MAIL_PASS` | Credentials                                          |
| `MAIL_FROM`               | "From" address on outgoing mail                      |

### LiveKit (optional)

If unset, voice channels return a "not configured" error.

| Var              | Description                                |
| ---------------- | ------------------------------------------ |
| `LIVEKIT_SERVER` | `ws://localhost:35105` locally             |
| `LIVEKIT_KEY`    | API key (`devkey` locally)                 |
| `LIVEKIT_SECRET` | API secret (long string in `.env.example`) |

### Handles (optional)

| Var                  | Description                                                                                     |
| -------------------- | ----------------------------------------------------------------------------------------------- |
| `HANDLE_DOMAIN`      | Default domain for handles (e.g., `mikoto.io`).                                                 |
| `HANDLE_PRIVATE_KEY` | Base64 Ed25519 private key for signing attestations. Generate with `just generate-handle-keys`. |
| `HANDLE_PUBLIC_KEY`  | Base64 Ed25519 public key for verifying.                                                        |

Without `HANDLE_PRIVATE_KEY` / `HANDLE_PUBLIC_KEY`, custom-domain
handles are disabled but default-domain handles still work.

### Web Push (optional)

| Var                 | Description                                               |
| ------------------- | --------------------------------------------------------- |
| `VAPID_PRIVATE_KEY` | URL-safe base64 raw 32-byte P-256 private key.            |
| `VAPID_PUBLIC_KEY`  | URL-safe base64 uncompressed P-256 public key (65 bytes). |
| `VAPID_SUBJECT`     | `mailto:admin@example.com` or an `https://` URL.          |

Generate all three with `just generate-vapid-keys`.

## Client

Vite picks up env vars from `apps/client/.env*` files. Anything that
should ship to the browser must be prefixed `PUBLIC_`.

| Var                                | Description                                    |
| ---------------------------------- | ---------------------------------------------- |
| `PORT`                             | Client dev server port (default `3510`).       |
| `PUBLIC_SERVER_URL`                | Where to reach superego from the browser.      |
| `PUBLIC_MEDIASERVER_URL`           | Where to reach the media/CDN from the browser. |
| `PUBLIC_FRONTEND_URL`              | Used in generated invite links.                |
| `COLLAB_PORT` / `MEDIASERVER_PORT` | Reserved for future split services.            |

For the `just run-client-prod` flow there's a committed
`apps/client/.env.prod-backend` that wires the dev server up to prod
through the same-origin proxy. See
[Dev against prod](/docs/client/dev-against-prod).
